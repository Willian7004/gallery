常见的数据库支持文件存储的方式主要有两种：直接存储二进制数据（如 BLOB 类型）或通过外部文件系统存储并管理元数据。以下是支持文件存储的常用数据库及其特点：

---

### **1. 关系型数据库 (RDBMS)**
#### **MySQL**
- **支持方式**: BLOB (Binary Large Object) 类型。
- **特点**:
  - 支持 `TINYBLOB`、`BLOB`、`MEDIUMBLOB`、`LONGBLOB`（最大 4GB）。
  - 适合存储中小型文件，但大文件可能影响性能。
  - 可通过 `LOAD_FILE()` 函数读取本地文件。

#### **PostgreSQL**
- **支持方式**: `BYTEA` 类型或大对象 (`Large Object`)。
- **特点**:
  - `BYTEA` 适合存储较小二进制数据（如几 MB）。
  - 大对象支持流式读写，适合大文件（需使用 `lo_*` 函数管理）。

#### **Microsoft SQL Server**
- **支持方式**:
  - **FILESTREAM**: 将文件存储在文件系统中，数据库管理元数据。
  - **FileTable**: 基于 FILESTREAM，提供文件系统与 SQL 表的集成。
- **特点**:
  - 适合大文件存储，性能优于直接存 BLOB。
  - 支持 Windows 文件系统 API 访问。

#### **Oracle**
- **支持方式**:
  - **BLOB**: 存储二进制数据。
  - **BFILE**: 存储指向外部文件的指针（文件保存在服务器文件系统中）。
- **特点**:
  - `BFILE` 适合不频繁修改的大文件，减少数据库负载。

---

### **2. NoSQL 数据库**
#### **MongoDB**
- **支持方式**:
  - **GridFS**: 将文件分块存储为文档（默认分块大小 16MB）。
  - 可直接存储小文件为 `BinData` 类型。
- **特点**:
  - 适合大文件存储（如视频、音频），支持分布式存储和分片。
  - 自动处理文件分块与元数据。

#### **CouchDB**
- **支持方式**: 通过 `_attachments` 字段存储文件。
- **特点**:
  - 文件与文档绑定，支持版本控制。
  - 适合文档与附件关联的场景（如 CMS 系统）。

#### **Cassandra**
- **支持方式**: `BLOB` 类型。
- **特点**:
  - 适合分布式存储，但大文件可能影响读写性能。
  - 通常建议存储小文件或文件元数据，大文件通过外部存储（如 HDFS）。

---

### **3. 专用文件存储数据库/工具**
#### **Amazon S3 (非传统数据库，但常配合使用)**
- **特点**:
  - 云对象存储服务，通过 REST API 管理文件。
  - 常与数据库（如 RDS、DynamoDB）结合使用，存储文件元数据。

#### **MinIO**
- **特点**:
  - 开源对象存储，兼容 S3 API。
  - 适合私有云或混合云环境的大规模文件存储。

#### **Hadoop HDFS**
- **特点**:
  - 分布式文件系统，适合存储海量文件。
  - 通常与 HBase 或 Hive 配合使用，管理文件元数据。

---

### **4. 嵌入式数据库**
#### **SQLite**
- **支持方式**: `BLOB` 类型。
- **特点**:
  - 轻量级，适合本地应用或移动端存储小文件（如缓存图片）。

---

### **5. NewSQL 数据库**
#### **CockroachDB**
- **支持方式**: `BYTES` 类型。
- **特点**:
  - 分布式架构，适合存储小文件或元数据，大文件建议结合外部存储。

---

### **选择建议**
- **小文件（<10MB）**: 直接使用数据库的 BLOB/BYTEA 类型。
- **大文件（>10MB）**: 优先使用外部存储（如 S3、GridFS、FILESTREAM）结合元数据管理。
- **高并发场景**: 考虑分布式存储（如 MinIO、HDFS）或 NoSQL 数据库（如 MongoDB）。

如果需要高扩展性和低成本存储，推荐组合使用数据库（存储元数据） + 对象存储（存储文件）。
